# 「キャプションを作る」を単純化する仕様検討メモ

ステータス: **register①(項目を決める)は実装・検証済み。それ以外は検討中・未実装**
作成日: 2026-09-22

## 背景・課題

Qriine が広まらない一因は、モバイル対応の不備(すでに大半修正済み)だけでなく、
「使うのが大変」「展覧会直前に慣れない操作をしたくない」という心理的ハードルにある。
これを抜本的に下げるため、既存の全画面を作り直すのではなく、**意思決定の数そのものを減らす**方向で検討している。

## スコープ

- **展覧会設定(setup.html / register.html)は現状維持**が前提。今回はここには手を入れない。
- 単純化の主戦場は**「キャプションを作る」体験(caption.html 周辺)**に絞る。
- 印刷物・キャプションのレイアウトという「UI 自体に価値がある領域」の話であり、
  CLAUDE.md の留保(UI = 単なる見せ方ではない領域がある)に該当する。

## 決定事項

### 1. 作家招待 vs 自分で入力
- 機能はそのまま残す。
- ただし「自分で入力」を優先表示にする(register② の並び・強調を変える程度の変更)。
- 理由: 招待方式は「作家がちゃんと提出してくれるか」という主催者のコントロールが効かない不安要素になり得る。
  個展ではほぼ使われず、グループ展でも作家が少なければ自分で集約する方が心理的に安全。
- **register①→③の遷移も合わせて見直す**: 現状すでに①保存後にバナーで
  「作家に登録してもらう→②作家を招待」「自分で入力する→③作品」の2ボタンを出す仕組みがあるが、
  対等な2択で提示されており、初めての人がどちらを選ぶか一瞬立ち止まってしまう。またバナーを見逃すと、
  タブを自分で見つけて移動する必要がある。
  → 「自分で入力する→③作品」を**大きく目立つ「次へ」ボタン**にして既定の道にし、
    「作家に依頼したい場合はこちら」は控えめなリンクとして脇に添える形に変更する。
  - **実装済み(2026-09-22)**: `saveSettings()` 内の保存後メッセージを変更済み。目視レビューで確認
    (マークアップの単純な入れ替えのため、別途スクリーンショット検証は省略)。

### 2. 個展 / グループ展の分類
- 「自分で入力」がデフォルトになった結果、これを最初に聞いても聞かなくても**操作フロー自体は変わらない**。
- 聞くこと自体は害がないので、ラベル・参考情報として残す分には良い(必須ではない)。

### 3. 集める項目(register①: 項目を決める)
- **ステップ自体は残す**(いったん「最初には聞かない」で検討したが撤回)。
  - 理由: 作家に自分で入力してもらう運用の場合、後から項目を追加すると作家に聞き直すことになり、
    「直前に何かまずいことをしたくない」という課題に逆行するため、事前に決めておく価値がある。
  - **実例による裏付け**: 個展のキャプションを作りたいがアプリを全く知らない人に聞いたところ、
    「項目の選択肢が見えること自体」で「何を用意すればいいか」が腑に落ちた、という反応があった。
    → 項目一覧を隠さず見せることには実際に理解を助ける効果がある。
- ただし中身は軽くする。今の約25項目(GRID_FIELDS)の全部載りグリッドをいきなり見せるのは
  情報過多になるため、以下の段階表示にする:
  - **最初に見せるのは `DEFAULT_FIELDS`(画像・タイトル・制作年・技法・サイズ・作家名・価格の7項目)のみ**、チェック済みで一覧表示。
    「これでよければ次へ」で済ませられるようにする。
  - その下に**ジャンル単位でまとめて選べるチップ**を用意し、ワンタップで関連項目を追加できるようにする。
    **版画・写真・国際展の3つに絞る**(下記参照):
    - 「版画・エディションがある」→ `edition`・`sheet_size`・`image_size` を追加
    - 「写真展」→ `shooting_location`・`shooting_year`・`camera` を追加
    - 「国際展・英語併記が要る」→ `title_en`・`artist_en` を追加(`official_intl` テンプレートに対応)
    - **インスタレーションチップは見送り**: 版画・写真・国際展には専用の公式テンプレートが
      既にあり過去の実需要が伺えるが、インスタレーションに対応する公式テンプレートは10枚の中に存在せず、
      実需要が薄いと判断。項目設定はいつでも変更可能なので、要望が出た時点で追加すれば良い。
- **実装・検証済み(2026-09-22)**: `public/register.html` に実装完了。
  - CSS: `#sortContainer.collapsed .field-card.secondary:not(.active) { display:none; }` で折りたたみを実現。
  - `makeFieldCard` で非デフォルト項目(`!def.isDefault`)に `.secondary` クラスを付与。
  - `GENRE_CHIP_FIELDS` マップ + `toggleGenreChip` / `syncGenreChips` / `toggleShowMoreFields` を追加。
  - 検証: 実コードを複製したテストハーネス(Firebase 認証部分のみ除去)をheadless Chromeでスクリーンショット確認。
    新規展覧会(既定7項目のみ表示+チップで拡張)と既存展覧会(非デフォルトのチェック済み項目が隠れず表示)の
    両ケースで想定通りの挙動を確認済み。
  - 上記のチップに当てはまらない残り(証明書・コレクション・クレジット・SNS等、使用頻度の低い項目)は
    「他の項目を見る」リンクの先に畳んでおき、通常は表示しない。
  - 増やすのはいつでも安全、減らすのは既入力データが隠れる非対称性があるため、
    チップで一旦決めたあとの追加変更は引き続き項目設定画面からいつでも可能とする。
- **互換性**: この変更はあくまで表示の仕方だけで、データの持ち方(`registration_fields` を
  `[{name, required}, ...]` の JSON 配列として展覧会ドキュメントに保存する形式)は変更しない。
  - 新規展覧会(未選択状態)では、DEFAULT_FIELDS 7項目+チップのみ表示し、残りは折りたたむ。
  - 既存展覧会は、DEFAULT_FIELDS 以外の項目をすでにチェックしていても、**チェック済みの項目は
    折りたたみの中に隠さず常に見える**ようにする(折りたたみ対象は「未選択の項目」に限定)。
    チェックが消えたように見える事故を防ぐため。
  - input.html / caption②(載せる項目) / CF は `registration_fields` の形式が変わらないため無改修。

### 4. キャプションのテンプレート選択(caption①)
- ラベル(🎨個展/🎭グループ展等)や自動推奨ロジックで選ばせるのはやめる。
  - 理由: テンプレートは見た目(フォントサイズ・配置)とデータ(どの項目を表示するか)の両方の違いがあり、
    見た目の良し悪しはアルゴリズムで判定できない(好みの問題)。ラベルも実態を表せていない。
- 代わりに、**実際に登録された作品データを流し込んだプレビューを並べて一覧表示し、目で見比べて選ぶ**方式にする。
  - 現状すでに各テンプレカードをクリックするとプレビューが更新される仕組み(`selectTemplate`)があるので、
    これを1枚ずつのクリック比較ではなく、一覧同時表示に変える改修になる見込み。
  - QR のみ(NY スタイル)テンプレートは、この一覧には**出さない**(次回検討事項参照)。

### 5. 項目の並び順
- 独立したステップにしない。`field-defs.js` の正準順序(タイトル→作家名→制作年→技法→サイズ→価格...)を既定にする。
- テンプレートのプレビューにはこの並びをそのまま反映する。個別の並び替えは詳細編集(caption③)のみで行う。
- 理由: 並び順を自由入力にすると、どのテンプレートとも一致しない組み合わせが生まれ、
  「見て選ぶだけで完了」という前提が崩れるため。

### 6. 用紙サイズ・向き・何個取り
- 用紙サイズ(A4 / レター)だけは軽い1問として残す(既定 A4)。国内/海外向けで実務的に必要な判断のため。
- 向き・何個取り(2×4, 3×5 等)は独立して聞かない。各テンプレートに既に `pageSettings` として
  紐付いており、プレビュー一覧に実際の紙面比率がそのまま出るため、テンプレ選びに自然に織り込まれる。

### 7. 縦長テンプレートの拡充
- 現状 10 枚中 9 枚が横長(105×74mm 等)、縦長は「QR のみ(NY スタイル)」の36×44mmのみ。
- 日本国内の主催者が多数を占める現状では、横長中心のままで実需要と大きくズレていないと判断。
  縦長を急いで増やす優先度は低い(将来、海外向け利用が増えたら再検討)。

### 8. QR のみ(キャプションなし)テンプレート
- 「現代アートギャラリーはキャプション自体がない場合も多い」という声はあるが、
  **大多数の主催者にはついてこられない選択肢**と判断し、簡単設定の入口には出さない。
- 機能・テンプレート自体は削除せず、従来通り詳細側(caption の10枚テンプレート一覧)に残す。

### 9. ページ設定(caption④)の残り(用紙サイズ以外)
- QR ラベル・QR 位置・QR サイズ・余白(QR/テキスト)・フォントは、いずれもすでに各公式テンプレートの
  `pageSettings` に既定値として紐付いている(例: QRサイズ22mm、余白3mm/6mm、フォントsans-serif等)。
- 用紙サイズ(A4/レター)以外は、並び順・向き・何個取りと同じロジックで**プレビュー一覧から選んだ時点で決まる**ため、
  個別に聞かない。触りたい場合のみ④ページ設定タブで調整(現状の画面をそのまま使う)。

### 10. 詳細編集(caption③)
- 今回の設計では「一覧プレビューで気に入るものがなかった人だけが入る場所」という位置づけになる。
- スマホでは本質的に厳しいという既存の判断(PCが楽、のヒント表示)がすでにあるため、
  この画面自体をさらに簡単にする改修は**今回のスコープに含めず、現状維持**とする。
  見て選ぶギャラリーが機能すれば、ここに辿り着く人自体が少数になる想定。

## 関連構想

### Lite 版は「本番の代替」ではなく「1分お試しデモ」として位置づける
- [[project_qr_only_lite_mode]] で検討していた Lite 版(設定画面なし・QR+キャプションのみ)は、
  結局「入力→キャプション設計」という核の作業自体は本番と変わらないため、**本番用途の代替にはならない**と判断。
- 代わりに、**ログイン不要・データ保存もほぼ不要な「作品を1点適当に入力→その場でキャプションとQRが出る」
  だけの1分デモ**として位置づけ直す。ランキング・ダッシュボード等は不要。
- 役割は「使うのが大変そう」で敬遠している人に、触ってみて「これだけのことか」と分かってもらう入口。
  実際に展覧会をやる段になったら、ここから本番(register/caption、今回整理した簡略化フロー)へ案内する。
- 本番機能の縮小版を継続メンテする話ではなくなるため、二重メンテのリスクは大きく下がる。

### 進捗アシスタント(準備状況のサジェスト機能) — 次回以降の検討事項
- 「展覧会を作る→項目設定→作品登録→キャプション確定→印刷」という一連の流れの中で、
  **今どこまで終わっていて、次に何をすればいいか**をシステム側からサジェストする機能があると良いのでは、という案。
  「作品登録がまだなら、そこへ飛ぶ導線を出す」等。
- 現状、専用の「進捗履歴」を記録する仕組みはない。ただし多くの状態は**既存データから導出可能**なはずで、
  新規の記録機構を必ずしも必要としない:
  - 項目設定済みか → `registration_fields` の有無
  - 作品登録が進んでいるか → 作品件数(0件かどうか)
  - キャプションが確定しているか → `caption_template_id` が preset 参照のままか、展覧会用に保存済みか
  - 印刷したかどうか → **これは現状追えない**(印刷ボタン押下のログが無い)。トラッキングするなら新規実装が必要。
- 以前の検討(本メモ作成前のやり取り)で出た「案C: 準備状況チェックリストを常設する」と同じ方向性。
  今回のスコープ(register①/caption①の簡略化)がある程度形になった後、着手を検討する。

#### 2026-09-23 仕様合意・実装

register① の実地評価で「項目削減の効果はさほど大きくなく、次に何をすればいいか示す方が重要かも」となり、
caption① のギャラリー化より先にこちらを実装した。

- **形: 右下のポップアップ**。「準備 n/4」ボタン → 押すとパネル (スマホは下からのシート)。
  上部の帯や専用画面ではなくポップアップにしたのは、**将来アシスタント機能 (質問応答・印刷前の警告・AI との対話等)
  を育てる器にするため** (ユーザー提案)。別ウィンドウではなく同一ページ内に重ねる。
- **出す画面**: register / caption / reports / setup の作成完了画面。作家用の input.html には出さない。
- **自動で開くのは2場面だけ**: 何も済んでいない展覧会を開いた最初の1回 (タブごと) と、ステップが済んだ直後。
- **必須の流れ**: 項目を決める → 作品を入力 → キャプションを決める → 印刷。未着手の最初のステップを
  「次はこれ」として該当画面・タブへ直行させる (register.html に `?tab=` と `&import=1` を追加)。強制はしない。
  作品が途中 (例 12/20) でも後続は止めない (作品枠が多めに取られていることがあるため)。
- **項目設定は必須ステップ** (「一旦はやって貰った方が良い」)。①の保存時に `fields_confirmed_at` を記録。
  記録は共通の保存関数 `fsSaveRegistrationFields` に入れたので、「他の展覧会から設定を複製」でも済みになる。
  caption のテンプレ採用で項目が自動追加されただけでは済みにしない (見て決めたことにならないため)。
  記録開始前に作られた展覧会は、項目が GAS 初期値 5 項目から変わっていれば済みとみなす。
- **前の展覧会の再利用**: 複製で項目設定・キャプションとも済みになる。過去の展覧会がある主催者には
  「次はこれ」に「前回の展覧会から設定を複製する」も並べる。
- **印刷は記録する**: キャプション印刷・QR 印刷の画面を開いた時点で `caption_printed_at` を記録。
- **「作家に依頼」はステップにしない** (送信履歴が残らず判定できない。作品数の進みでカバー)。
- **任意項目** (Web 展覧会・感想の受付期間・本番切替) は折りたたみの別枠。開始日があれば「会期まであと N 日」。
- **構造**: 判定は `public/js/progress-core.js` (純粋関数、テスト `functions/scripts/test-progress.js`)、
  取得と描画は `public/js/progress-assistant.js`。AI アシスタントを載せるときも同じ判定を使い、
  画面と AI の言うことをずらさない (設計原則4)。必要になれば判定を Cloud Function に移す。

## 前提・非目標

- 既存の Firestore データモデル・Rules・CF ロジックは変更しない前提で検討している
  (今のところ新しいフィールドの永続化は発生しない見込み)。
- 既存の詳細設定画面(register/caption のフル機能)は一切削除・縮小しない。単純化ルートはあくまで追加の入口。
